## 1. 產品概述（摘要）

親師溝通平台，分**家長端**與**老師端**兩套介面（同一 App、依角色渲染）。定位是「結構化、可回報追蹤、老師省力、家長省心、且能留存孩子成長」，藉此贏過 LINE 群組＋紙本聯絡簿。完整定位與功能見 `SPEC.md §0`。

**角色**：老師（導師，管理自己班級）、家長（一帳號可綁一或多個孩子，只看自己孩子）。

## 2. 技術棧與架構

| 層 | 選型 | 備註 |
| --- | --- | --- |
| 前端框架 | **React 18 + TypeScript** | 函式元件 + Hooks |
| 建置 | **Vite** | 快、PWA 外掛完整 |
| 路由 | **React Router v6** | 見 §9 |
| 伺服端狀態 | **TanStack Query v5** | 快取、樂觀更新、離線持久化 |
| 資料/後端 | **Supabase** | Postgres + Auth + Storage + Realtime + Edge Functions |
| 樣式 | **原生 CSS（沿用 demo）+ CSS Modules** | 不引入 Tailwind/UI 套件，確保外觀一致（見 §10） |
| 表單 | React Hook Form（選用） | 輕量即可，demo 表單很簡單 |
| PWA | **vite-plugin-pwa（Workbox）** | 可安裝 + 離線讀取 + Web Push |
| 推播 | **Web Push（VAPID）+ Supabase Edge Function** | 見 §11 |
| 部署 | 前端 Vercel / Netlify / Cloudflare Pages；後端 Supabase 雲 | 見 §14 |

**資料流（單向、以 Supabase 為單一真實來源）：**

```
UI 元件 ──呼叫──▶ services/*.ts（封裝 supabase-js）──▶ Supabase (Postgres + RLS)
   ▲                                                          │
   │                                                          ▼
TanStack Query 快取 ◀── Realtime 訂閱（postgres_changes, 依 class_id 過濾）
```

- **讀**：元件用 Query hooks（`useXxx`）取資料；Query 呼叫 `services/*.ts`。
- **寫**：元件呼叫 service mutation → 成功後 invalidate 對應 query key；同時 Realtime 會把其他裝置的變更推來，達成 SPEC L12「老師改，家長即時看到」。
- **權限**：一律靠 RLS。前端只負責 UX 層的顯示過濾（SPEC L2）。

## 5. 資料模型（Supabase / Postgres schema）

> 對照 demo：demo 是「單班、單孩子、localStorage」；正式版是「多班、多孩子、多家長、RLS 隔離」。
> 所有表都要 `alter table ... enable row level security;`（見 §6）。

### 5.1 Enums

```sql
create type role_t         as enum ('teacher','parent');
create type event_type_t   as enum ('exam','activity','fee','holiday');
create type leave_type_t   as enum ('sick','personal','late');          -- 病假/事假/遲到
create type leave_status_t as enum ('pending','approved','rejected');
create type photo_vis_t    as enum ('class','guardians','private');     -- 見 SPEC 隱私
create type sender_role_t  as enum ('teacher','parent');
```

### 5.2 核心表

```sql
-- 使用者檔案（1:1 對應 auth.users）
create table profiles (
  id            uuid primary key references auth.users(id) on delete cascade,
  role          role_t not null,
  display_name  text not null,
  locale        text not null default 'zh-Hant',
  created_at    timestamptz not null default now()
);

-- 班級（老師擁有）
create table classes (
  id            uuid primary key default gen_random_uuid(),
  teacher_id    uuid not null references profiles(id) on delete cascade,
  name          text not null,                     -- 例：一年甲班
  office_hours  text default '平日 17:00–20:00',   -- 私訊回覆時段
  created_at    timestamptz not null default now()
);

-- 學生（孩子）
create table students (
  id         uuid primary key default gen_random_uuid(),
  class_id   uuid not null references classes(id) on delete cascade,
  seat       text not null,                        -- 座號，如 '07'
  name       text not null,
  created_at timestamptz not null default now(),
  unique (class_id, seat)
);

-- 家長 ↔ 學生（多對多；一孩子可多家長、一家長可多孩子）
create table guardianships (
  id         uuid primary key default gen_random_uuid(),
  student_id uuid not null references students(id) on delete cascade,
  parent_id  uuid not null references profiles(id) on delete cascade,
  relation   text,                                 -- 爸爸/媽媽/阿嬤…
  unique (student_id, parent_id)
);

-- 邀請碼（老師產生，家長憑碼綁定某學生）
create table invites (
  id         uuid primary key default gen_random_uuid(),
  class_id   uuid not null references classes(id) on delete cascade,
  student_id uuid references students(id) on delete cascade, -- 綁定到特定孩子
  code       text not null unique,                 -- 短碼，如 8 碼
  expires_at timestamptz,
  used_at    timestamptz,
  used_by    uuid references profiles(id),
  created_by uuid not null references profiles(id),
  created_at timestamptz not null default now()
);
```

### 5.4 衍生/計算值（不落庫，前端或 SQL view 計算，對照 SPEC L4/L5/L9）

- **成績級距與 percentile**：由 `scores` 即時算（桶：90–100/80–89/70–79/60–69/59以下）。
- **公告已讀數**：`count(announcement_reads)` / 班級家長數。
- **同意書簽署率、未簽名單**：`students` 對 `consent_signatures` 差集。
- **成長時間軸/紀念冊**：`milestones` + 成績里程碑（exam.published 且該生有分數）+ `performance_notes` 合併排序。

可提供 view 方便前端讀，例如：

```sql
create view v_announcement_read_stats as
select a.id as announcement_id, a.class_id,
       count(distinct r.parent_id) as read_count,
       (select count(distinct g.parent_id) from students s
          join guardianships g on g.student_id = s.id
        where s.class_id = a.class_id) as guardian_count
from announcements a
left join announcement_reads r on r.announcement_id = a.id
group by a.id;
```

## 6. 權限與隱私（RLS）— 最重要章節

> demo 靠前端過濾；正式版必須靠 RLS。以下政策要落實 SPEC L1（資料隔離）。
> 家長只能存取「自己孩子」；老師只能管「自己班級」。

### 6.1 輔助函式（security definer）

```sql
create or replace function is_teacher_of(cid uuid) returns boolean
language sql security definer stable as $$
  select exists(select 1 from classes c where c.id = cid and c.teacher_id = auth.uid());
$$;

create or replace function is_guardian_of(sid uuid) returns boolean
language sql security definer stable as $$
  select exists(select 1 from guardianships g
                where g.student_id = sid and g.parent_id = auth.uid());
$$;

-- 目前使用者是否為某班成員（老師或該班任一孩子的家長）
create or replace function is_class_member(cid uuid) returns boolean
language sql security definer stable as $$
  select is_teacher_of(cid)
      or exists(select 1 from students s
                join guardianships g on g.student_id = s.id
                where s.class_id = cid and g.parent_id = auth.uid());
$$;
```

### 6.2 政策範式（每張表都要）

**班級層資料（公告/攜帶/行事曆/同意書表頭…）— 老師寫，全班讀：**

```sql
alter table announcements enable row level security;

create policy ann_read on announcements for select
  using ( is_class_member(class_id) );

create policy ann_write on announcements for all
  using ( is_teacher_of(class_id) )
  with check ( is_teacher_of(class_id) );
```
（`events`、`bring_items`、`homework_items`、`consent_forms`、`exams` 套同一範式。）

**學生私有資料（成績/亮點/里程碑/請假/私訊）— 老師管全班，家長只讀自己孩子：**

```sql
alter table scores enable row level security;

-- 老師：讀寫自己班學生的分數
create policy scores_teacher on scores for all
  using ( exists(select 1 from exams e where e.id = exam_id and is_teacher_of(e.class_id)) )
  with check ( exists(select 1 from exams e where e.id = exam_id and is_teacher_of(e.class_id)) );

-- 家長：只讀自己孩子、且該 exam 已發布
create policy scores_parent_read on scores for select
  using ( is_guardian_of(student_id)
          and exists(select 1 from exams e where e.id = exam_id and e.published) );
```

**成績「級距」隱私（SPEC L4）**：個人分數以上面 policy 鎖到「自己孩子」；全班級距是**去識別化聚合**，用 view/RPC 回傳（只有各分數帶人數，不含姓名），且需 `exam.show_dist = true`。前端呼叫 `getDistribution(examId)`（§8）。

**家長勾選作業（homework_status）：**

```sql
alter table homework_status enable row level security;
create policy hw_status_parent on homework_status for all
  using ( is_guardian_of(student_id) )
  with check ( is_guardian_of(student_id) );
create policy hw_status_teacher_read on homework_status for select
  using ( exists(select 1 from homework_items h where h.id = homework_id and is_teacher_of(h.class_id)) );
```

**已讀回條：** 家長只能新增/讀自己的；老師讀聚合（用 §5.4 的 view，view 亦受 RLS 限制或改 security definer RPC）。

```sql
alter table announcement_reads enable row level security;
create policy reads_parent on announcement_reads for all
  using ( parent_id = auth.uid() ) with check ( parent_id = auth.uid() );
```

**請假：** 家長對自己孩子 insert/select；老師 select/update（審核）。

```sql
alter table leaves enable row level security;
create policy leaves_parent on leaves for select using ( is_guardian_of(student_id) );
create policy leaves_parent_insert on leaves for insert with check ( is_guardian_of(student_id) and parent_id = auth.uid() );
create policy leaves_teacher on leaves for all using ( is_teacher_of(class_id) ) with check ( is_teacher_of(class_id) );
```

**同意書簽署：** 家長對自己孩子 insert/select；老師 select 全班。
**私訊：** conversation 屬於某 class+student；老師（班導）與該 student 的家長可讀寫；訊息 insert 的 `sender_id` 必須等於 `auth.uid()`。

```sql
alter table messages enable row level security;
create policy msg_access on messages for select using (
  exists(select 1 from conversations c where c.id = conversation_id
         and ( is_teacher_of(c.class_id) or is_guardian_of(c.student_id) ))
);
create policy msg_send on messages for insert with check (
  sender_id = auth.uid()
  and exists(select 1 from conversations c where c.id = conversation_id
             and ( is_teacher_of(c.class_id) or is_guardian_of(c.student_id) ))
);
```

**Storage（photos bucket）**：用 Storage RLS，路徑前綴含 class_id，policy 檢查 `is_class_member`。上傳限老師。

> ✅ 驗收：以「家長 A 的 token」嘗試讀家長 B 孩子的分數/照片/私訊，必須全部被 RLS 擋下（回空或 403）。

## 7. 認證與帳號流程（邀請制）

### 7.1 老師
1. Email 註冊/登入 → 建立 `profiles(role='teacher')`（用 auth trigger 自動建 profile）。
2. 建班 `classes` → 新增學生 `students`（座號、姓名，可 CSV 批次）。
3. 為每位學生產生 `invites`（短碼 + 連結 `/join/:code`，可設到期）。

### 7.2 家長
1. 開啟邀請連結 `/join/:code` → Email 註冊/登入。
2. 呼叫 Edge Function `redeem_invite`（security definer，原子性）：
   - 驗證 code 未過期未使用；
   - 建立/更新 `profiles(role='parent')`；
   - 建立 `guardianships(student_id, parent_id)`；

### 7.3 auth trigger（自動建 profile）

```sql
create or replace function handle_new_user() returns trigger
language plpgsql security definer as $$
begin
  insert into profiles(id, role, display_name)
  values (new.id, coalesce((new.raw_user_meta_data->>'role')::role_t,'parent'),
          coalesce(new.raw_user_meta_data->>'display_name','使用者'))
  on conflict (id) do nothing;
  return new;
end; $$;
create trigger on_auth_user_created after insert on auth.users
  for each row execute function handle_new_user();
```

### 8.4 即時同步（Realtime）

用 `postgres_changes` 依 `class_id` 過濾，變更時 invalidate 對應 query：

```ts
// realtime.ts
export function subscribeClass(classId: string, onChange: (table: string) => void) {
  const ch = supabase.channel(`class:${classId}`);
  ['announcements','homework_items','homework_status','bring_items','exams','scores',
   'events','leaves','consent_signatures','messages','performance_notes','milestones']
    .forEach(t => ch.on('postgres_changes',
      { event: '*', schema: 'public', table: t, filter: `class_id=eq.${classId}` },
      p => onChange(t)));
  ch.subscribe();
  return () => supabase.removeChannel(ch);
}
```

> 這實現 SPEC L12：老師任何發布，家長端即時看到（跨裝置）。`messages` 表無 class_id 欄位，改用 `conversation_id` 過濾另開 channel。

## 18. 為「後續調整」而設計：讓改動又快又穩

> 目標：未來要新增/調整功能時，負責的 agent 能**快速**動手、又**不弄壞**既有功能（穩定最重要）。以下是建置期就要鋪好的「軌道」。

**建議工作流（要不要回 demo 調）：**
- **小到中的功能調整/新增** → 直接在正式專案開發，不要繞回 demo（避免 demo 與正式版分歧 drift）。
- **要探索全新的 UX/視覺方向、想快速抓「感覺」** → 可回到 demo（`index.html`，零後端摩擦最適合玩感覺）或在 Storybook 試；定案後再落地。
- 前提：把下面 10 條軌道鋪好，正式專案就能「留著直接開發」且穩。

**要鋪好的 10 條軌道：**
1. **`AGENTS.md`（最關鍵）**：把慣例、資料夾意義、如何跑測試、禁止事項、每種功能的「新增步驟範本」寫成機器可讀規則。這是讓 agent 快又穩的最大槓桿。
2. **設計系統即程式 + Storybook**：把 demo 的 token/元件做成元件庫並用 Storybook 展示；Storybook 成為新的視覺真實來源（可取代「回 demo」的需求）。
3. **視覺回歸測試**（Chromatic 或 Playwright 截圖快照）：不小心動到外觀會被擋下 → 穩。
4. **端到端型別**：`supabase gen types` 產生 DB 型別 + 領域型別；schema 一改，錯誤在編譯期浮現。
5. **資料存取層是唯一入口 + 契約測試**：所有查詢走 `services/*.ts`；agent 只透過這個接縫改資料，降低波及面。
6. **RLS 政策自動化測試（極重要）**：一組測試斷言「家長 A 不能讀家長 B 孩子的分數/照片/私訊」。每個新功能都要通過 → 隱私不回歸。
7. **一律用 migrations**：`supabase/migrations` 版本化、可回滾、附 seed；禁止手改 DB。
8. **Feature-sliced 架構**：每個功能自成一個資料夾（畫面/hooks/service 使用），改一個功能波及最小。
9. **種子資料 + staging 環境 + e2e（Playwright）**：覆蓋關鍵流程（登入、家長只看到自己孩子、老師發布→家長即時看到），改完能馬上跑起來看。
10. **CI 關卡**：typecheck / lint / 單元 / RLS 測試 / e2e 冒煙 / 視覺回歸 全過才能合併。這就是「改得快」同時「改得穩」的保證。
