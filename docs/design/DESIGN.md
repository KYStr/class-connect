> 本檔為本專案 UI 的**單一事實來源（single source of truth）**。任何人／任何 AI 在動 UI 前都必須先讀本檔，並嚴格依此實作。

## 1. Overview（設計綱要）

### 1.1 主題定錨（Ground it in the subject）
- **主題**：國小一年級的親師溝通平台。
- **對象**：家長（含不熟 3C 的長輩）＋ 一位導師。
- **這一頁唯一的任務**：讓家長 3 秒內看懂「我孩子今天要做什麼、明天要帶什麼」，並且**看見孩子的成長**；老師則能省力發布與掌握全班。
- **世界觀素材**：聯絡簿、貼紙集點、成長手冊、班級照片牆——設計語彙從這裡長出來，而不是通用 SaaS。

### 1.2 美學方向（承諾一個，不走 AI 預設）
- **選定調性：Warm Editorial（溫暖刊物感）＋ Soft Depth（柔和層次）**。
- 感覺：像一本編排精緻的親子成長刊物 App——溫暖、可信、專業，不幼稚、不花俏。
- **刻意避開** Anthropic 點名的三種 AI 預設外觀：①奶油底＋高對比襯線＋赤陶色；②近黑底＋單一螢光色；③報紙式細線無圓角密欄。我們走「暖白紙感＋青綠/暖橘語意色＋圓角柔層次」。

### 1.3 Hero 即論點（The hero is a thesis）＋ Signature（招牌元素）
- **招牌元素（整個產品被記住的那一個東西）＝「今日 feature 主角區塊」**：一塊彩色卡，左邊是**環形完成度**、右邊是襯線大標（例：「還有 2 項要完成」）。
- 它同時體現兩個核心價值：**一眼搞定**（進度環）＋**看見孩子**（成績頁的分數 hero 同款語言）。
- 「大數字＋小標＋漸層」是通用解答——我們只在成績 hero 使用它，因為分數本身就是重點；其餘畫面不重複這招。

### 1.4 把大膽花在一個地方（Restraint）
- 每個畫面只有**一個**視覺主角（首頁＝完成度 feature；成績＝分數 hero；表現＝孩子照片）。主角以外一律安靜、克制。
- Coco Chanel 原則：出門前對鏡子拿掉一件配件。做完每個畫面後，刪掉一個不服務主題的裝飾。

## 2. Colors（色彩 · 封閉 token 層）

> 規則：**只能使用語意 token，禁止硬寫 hex**。顏色代表語意，不隨畫面亂換。

```css
/* 中性 */
--ink:#212a33;        /* 主文字 */
--ink-soft:#4b5a67;   /* 次文字 */
--muted:#8a97a3;      /* 輔助、標籤、時間 */
--line:#e9edf1;       /* 分隔線、邊框 */
--paper:#fbfaf7;      /* 頁面暖白底 */
--card:#ffffff;       /* 卡片底 */

/* 家長端主色（信任、教育） */
--primary:#2f9e8f;
--primary-deep:#227a6e;
--primary-soft:#e4f4f1;

/* 老師端 / 明日攜帶 / 孩子自身成績（溫暖、突出） */
--accent:#f2994a;
--accent-soft:#fdefe1;

/* 語意輔色 */
--pink:#ef6f7b; --pink-soft:#fdeaec;   /* 重要 / 提醒 */
--blue:#4a86c5; --blue-soft:#e7f0f9;   /* 一般資訊 */
```

**用色規則（rationale）**
- 家長端主要動作／強調用 `--primary`；老師端與「明日攜帶」用 `--accent`。兩端配色即身份識別。
- 「重要」公告才用 `--pink`；一般資訊用 `--blue`。
- 孩子**自己的**成績用暖橘（`--accent`，親近、突出）；**全班級距**用青綠（`--primary`，中性、去識別化）。
- 「主色為主、銳利點綴」勝過平均分配的膽怯配色（frontend-design 原則）。

**對比 / 無障礙（WCAG 2.2 AA）**
- 內文一律用 `--ink` / `--ink-soft`，**不得**用 `--primary` / `--accent` 當小字內文（對比不足）。
- 彩色只用於：大標題、大數字、圖示、狀態標籤、彩色區塊上的白字。
- 彩色區塊白字須落在深段漸層（如 `--primary-deep`、`#e07f2f` 以深）以確保對比。

## 3. Typography（字體）

> 字體是頁面的個性載體，不是內容的中性容器。刻意配對，避開通用字體。

| 角色 | 字體 | 用法 |
| --- | --- | --- |
| Display 展示（招牌） | `Noto Serif TC` 700/900 | 大標題、頁面標題列標題、大數字（分數/統計）。**克制使用**，只給主角。 |
| Body 內文 | `Noto Sans TC` 400/700 | 一般文字、清單、按鈕、表單。 |
| Utility 數據/說明 | `Noto Sans TC` 600/700 | 標籤、時間、小提示、統計副標。 |

- **禁用**：Inter / Roboto / Arial / Space Grotesk 等通用字體。
- 型級（type scale）：標題字距收緊 `-0.01em`、行高 1.1；內文行高 1.6。
- 一個畫面最多兩種字體、三層字級。大數字（92 分、28 位、33%）一律用襯線 Display，這是我們的字體記憶點。

## 4. Spacing / Radius / Elevation（間距 · 圓角 · 層次）

```css
/* 間距節奏（px）*/  4 · 8 · 12 · 13 · 20        /* 區塊之間預設 12–13 */
/* 圓角 */
--r-card:20px; --r-btn:14px; --r-sheet:24px; --r-phone:50px; --r-pill:999px;
/* 陰影：雙層（近實＋遠柔）製造真實光感 */
--shadow-card:0 1px 2px rgba(31,45,58,.05), 0 12px 24px -18px rgba(31,45,58,.5);
--shadow-lift:0 34px 70px -30px rgba(31,45,58,.45);   /* 手機/浮起面板 */
--shadow-feature:0 2px 4px rgba(31,45,58,.06), 0 22px 36px -24px rgba(31,45,58,.7);
```

- **禁止 magic number**：間距/圓角只用上述尺度；不得硬寫任意 px。
- 深色元素（手機外框、feature）用漸層＋內緣反光製造材質，不是單一純色。

## 5. Layout & Signature（版式與招牌結構）

### 5.1 圖層結構（每個畫面共用）
```
狀態列
彩色標題列（班級膠囊 + 襯線大標題 + 登出）
┌───────────── 浮起圓角面板（--r-sheet，負 margin 疊在標題列上，頂部握把）
│   feature 主角區塊（僅主頁面）
│   內容卡片們（--shadow-card）
└─────────────
底部分頁（動態出現）
```
- 「浮起面板疊在彩色標題上」是我們的層次語言，取代平鋪色塊。

### 5.2 Signature 元件
- **feature 主角區塊**：彩色漸層卡＋白字＋**環形進度（SVG 雙圈，中央顯示 %）**。家長端青綠、老師端暖橘。
- **score-hero**：暖橘區塊＋超大襯線分數＋「勝過班上 X%」膠囊。

### 5.3 Structure is information（結構要承載真實）
- 我們**不**用裝飾性的 01/02/03 編號（內容不是有序流程）。
- 眉標、分隔線、標籤都要對應真實語意（例：重要=紅、一般=藍）。
- **「有發布才顯示」本身就是一種結構**：沒有的內容整塊消失，而不是留空或寫「無」。

## 6. Components（元件 · 每個都要定義完整狀態）

> Super Design 關卡：每個互動元件必須涵蓋 hover / active / focus-visible / disabled（適用者）狀態，且有 empty state。

| 元件 | 說明 | 必備狀態 |
| --- | --- | --- |
| Button 按鈕 | 主行動；青綠或暖橘漸層 | 預設 / hover 上浮 2px / active 回落 / focus-visible 外框 |
| Card 卡片 | 白底、`--r-card`、`--shadow-card` | — |
| Feature / Score-hero | 招牌彩色區塊 | 內含 ring / 大數字 |
| Ring 環形進度 | SVG 雙圈＋中央 % | 依數值呈現 |
| Progress bar | 細長條完成度 | 依數值成長 |
| Pill / Chip 標籤 | 狀態、攜帶物、級距；語意色 | — |
| Checkbox 勾選框 | 家長打勾 | 未選（描邊）/ 已選（填色＋勾勾動畫）|
| Switch 開關 | 老師顯示/公開控制 | 關（灰）/ 開（accent，或 green 變體）|
| Tab bar 分頁 | 底部導覽；**動態顯示** | 一般 / act（藥丸底＋亮色）|
| Input / Textarea / Select | 表單 | 預設 / focus（主色外框光暈）|
| Add row（＋） | 新增清單項 | hover 變主色 |
| Delete（✕） | 刪除項目 | hover 變紅 |
| Photo tile | 照片牆（demo 以色塊＋說明代替） | 老師端含刪除 |
| Note item | 表情＋標題＋描述＋時間 | — |
| Empty state | 空清單 | 圖示＋友善文案（見 §9）|

## 7. Motion（動態 · 只為強化層次）

- **換頁才播放**淡入（fadeUp）；資料同步更新時**不重播動畫、保留捲動位置**。
- Ring / progress / bar 依數值呈現；卡片與按鈕 hover 上浮。
- 一次編排良好的載入 > 到處零散的微動畫（frontend-design 原則）。
- **尊重 `prefers-reduced-motion`**：關閉時停用位移/淡入。
- 禁止：無敘事輪播、炫技動畫、會讓人覺得「AI 生成」的過度動態。

## 8. Voice & Writing（介面文案）

> 文字是設計材料，不是裝飾。目的只有一個：讓人更好懂、更好用。

- **站在使用者這一側說話**：用家長/老師認得的詞（「明天要帶」而非「攜帶物件清單」）。
- **主動語態、動作即結果**：「發布給全班家長」而非「送出」；按「發布」→ toast 說「已發布」，用詞全程一致。
- **空狀態是邀請，不是情緒**：「目前沒有公告 📭」「今天沒有作業 🎉」；錯誤要講清楚怎麼修，不裝可愛也不道歉。
- 語氣：口語、句首大寫（中文即自然句）、無贅字，貼近家長與長輩。
- 一個元素只做一件事：標籤負責標示、範例負責示範，不身兼二職。

## 9. Do's & Don'ts（反 AI-slop 硬規則）

**Do**
- ✅ 先承諾美學方向，再寫 code；每畫面一個視覺主角。
- ✅ 只用語意 token；彩色代表意義。
- ✅ 空清單一律有友善空狀態。
- ✅ 有發布才顯示欄位；沒資料整塊隱藏。
- ✅ 響應式到手機、鍵盤 focus 可見、尊重 reduced-motion。

**Don't**
- ❌ 通用字體（Inter/Roboto/Arial/Space Grotesk）。
- ❌ 白底紫色漸層、螢光科技風、賽博感。
- ❌ 整頁等大卡片堆疊、無層次；三欄卡片、置中 hero、四欄 footer 這類公版。
- ❌ 無敘事輪播、裝飾性 01/02/03 編號。
- ❌ 空欄位佔位「成績－無」。
- ❌ 硬寫 hex / magic number 尺寸。
- ❌ 假內容（lorem ipsum、John Doe、Item 1/2/3）——用真實情境文案。

## 10. Quality Gates（開發自檢 · 每次改動都要過）

- [ ] 只用語意 token，無硬寫 hex／無 off-scale 尺寸。
- [ ] 每個互動元件涵蓋 hover / active / focus-visible / disabled。
- [ ] 文字對比達 WCAG 2.2 AA（彩色不當小字內文）。
- [ ] 響應式在手機寬度正常；`prefers-reduced-motion` 生效。
- [ ] 每畫面只有一個視覺主角；招牌元素只出現在該出現的地方。
- [ ] 空清單有空狀態；沒發布的欄位/分頁不出現（對應 SPEC L2）。
- [ ] 文案為主動語態、使用者視角、動作即結果。
- [ ] 對照本檔 §2–§9 逐項符合；有偏離要寫明原因。
